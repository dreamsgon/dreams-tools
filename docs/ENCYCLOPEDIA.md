# RPG Encyclopedia

Open `/encyclopedia` from the RPG Tools home and sign in with the same account used for Maptable. Each account has its own encyclopedia. It includes worlds and campaigns, nested articles, wiki links/backlinks, search, tasks, character articles and custom tabs, calendars/moons/seasons, weather/travel, map atlases, fog, templates and player sharing.

## Source and migration

Imported from the owner's [TTRPG World Manager GPT Site](https://ttrpg-world-manager.dreamsleever.chatgpt.site), version 11, source commit `a310ac6e0e5f737437209be5fbaca5e10fb82157`, on 2026-11-10. The original site was not modified. This package contains its application source, synthetic demo content and templates, not your live private worlds or a rules encyclopedia database.

1. While signed into the old site, open Settings and export all worlds (or export a selected campaign).
2. For every uploaded atlas map, download its **Map package** too. Workspace JSON references image IDs; it does not embed the uploaded image bytes.
3. Sign into the new deployment, open the encyclopedia's Settings, and import the JSON. Imports create separate copies instead of silently replacing existing worlds.
4. Import the map packages into the appropriate campaigns/maps and check images, fog, article references and calendar content. Keep the original exports until everything is verified.
5. Create new player links and agent keys in the new deployment. Old Sites links and credentials do not migrate.

The encyclopedia workspace limit remains 2 MB; PNG/JPEG/WebP atlas images allow up to 8 MB each. Maptable and encyclopedia retain separate data formats; a map does not automatically synchronize between them. Data stays in the same configured private S3 bucket under separate per-account paths. Existing `MAPTABLE_` environment names serve both modules.

## Page text

Page text is Markdown with wiki syntax, read by `lib/encyclopedia/markup.ts` and drawn by `components/encyclopedia/wiki-prose.tsx` for the GM and for players. The full syntax is in the guide, `content/guide/Writing-Wiki-Pages.md`. GM-only parts (`::: secret` boxes, nested boxes counted; `%%asides%%`; lines starting `(gm)`) are removed on the server by `stripSecrets` before any player payload is built. HTML goes through the Forum's filter (`lib/forum/html.ts`) and is built as React elements, never set as HTML.

Pictures in page text are `![[picture:<image id>|Caption|left|small]]` lines, uploaded to the GM's map-image storage like any picture. Who may fetch one follows the text: a player fetches it when it is in a page tab they receive (`playerImageOwnerOf` in `lib/encyclopedia/store.ts`, after secrets are taken out), a co-GM when it is anywhere in their campaign's text. New picture ids in a co-GM's save must be ones they uploaded (`images()` in `co-gm-edit.ts`); a player's save can't add new ones (`savePlayerEdit`).

The campaign front page (`components/encyclopedia/campaign-home.tsx`) draws `campaign.look.banner` behind the campaign's name; the GM sets it there, in Look, or in the Admin CP's Banner tab, which saves through the forum's `banner` action into the Wiki workspace (revision-checked).

A page's own look is optional `entry.pageLook` (`lib/encyclopedia/page-text.ts`): a banner (`imageId`, size and `y`), an icon from `PAGE_ICONS` (drawn by `components/encyclopedia/page-icons.tsx` in the sidebar, quick search and player list), `box: 'left'` for info boxes, `toc: false` to hide On this page, and `wide`. Players receive it without `toc`; its banner can be fetched like the page's pictures.

## Character trackers

A character's **Stats** tab starts with **Trackers**: small gauges such as Shields, Stress, Ammo or Hit dice, shown as a bar or as pips, with − and + to move them. Add your own or start from a ready-made one, and use each tracker's eye to hide it from players. Players see the shown trackers when the character's stats are shared. A player who may edit the character, under its Who can edit, sees them at the top of the page on the player site, moves them with − and +, and can add, change or remove their own. A hidden tracker never reaches them.

## Inventory, spells and stores

Nothing here is tied to one game. **Items and spells** in the Tools menu sets them up for the campaign: the coins and what each is worth in the smallest one (one Coins, gold, silver and copper, credits, dollars and cents, or your own), how a load is counted (pounds, kilograms, slots, bulk or not at all), the item categories, which columns show (weight, value, uses, worn or in hand), what the game calls its spells (Spells and Cast, Powers and Use, Prayers…), their groups and the details each one lists (Range, Duration), the word for ready ones (Prepared, or none), and what players may do. Start from Fantasy, Science fiction, Modern day or Slots and one coin, then change any word. The **item list** there holds items you saved from a character to hand out again.

A character page has an **Inventory** tab: money (type amounts such as 5 gp 3 sp and choose Add or Spend; coins make change by themselves), how much they carry against what they can carry, and items in their categories. Each line has a quantity with − and +, a shield for worn or in hand, uses as pips, rolls to click, weight and value, and opens to a note (write [[2d6|Label]] for a roll in it), a GM note players never get, Give to… another character, and Save to the item list. The **Spells** tab (named by the campaign) groups spells, powers or prayers, each with its details, tags, text with rolls, rolls to click, a star for ready ones, and an optional cost: Cast (or the campaign's word) spends that many from one of the character's trackers, such as spell slots or power points. Every item and spell has an eye. Both tabs have their own tab visibility for other players; the character's own player (Who can edit) always sees them on the player site and changes them there, as the campaign allows. Sheet import fills Inventory from a list titled Inventory (or Equipment, Gear…), Spells from a list titled Spells (or Powers, Prayers…), with matching spell rolls, and money from the file's `money`; export writes them back.

Choose **Store** as the entry type for a shop, a container, a pile of loot or the party's stash (after Foundry's Item Piles). The **Stock** tab (Contents, Loot or Stash) lists items with category, how many (or ∞, never runs out), value and, in a shop, what players pay; a line can be hidden (under the counter) or be a service that is bought but not carried away. Each line opens to its note, GM note, weight, uses and rolls. Settings for the kind: a shop is open or closed with its hours, players pay a % of value and the shop pays a % when it buys, a category or a character can have its own %, the shop buys only some categories or nothing, its purse can never run out, sold-out lines can be hidden, characters can haggle once every two hours with a roll (a roll on their sheet, a stat by name or dice) against a target for a % off, and each sale can wait for your OK (Yes or No on the page). A container is open, closed (anyone opens it) or locked (a key the character carries by name, or a roll against a target). For containers, loot and stashes you choose whether players take things, put things in, take everything at once or split the coins between the party (the campaign's PCs). Any store can be for picked characters only and can be run by a character, whose player then stocks it from their inventory, sets prices and collects the coin (a stall). Players can set up their own stalls, containers and stashes from their Inventory tab when the campaign says Yes or After my OK. Every change is logged on the page. On the player site prices are worked out and rolls made on the server; players never get hidden lines, GM notes, the shop's purse, other characters' rates or deals, the key's name or a roll's target, or anything inside a closed container.

## Galaxies

Choose **Galaxy** as the entry type to start a space setting. A galaxy page opens on its **Galaxy** tab: the galaxy drawn from its shape, arms and seed, whether it is real or invented, a short summary and its facts (type, size across, stars, age and distance), each typed in place. **Real galaxy or generate** picks a real galaxy (the Milky Way, Andromeda, Triangulum, the Large Magellanic Cloud or Messier 87, with rounded published figures) or generates one from a shape, number of arms, size and seed. The same settings always draw the same galaxy. The Galaxy tab is for the GM; players see only the tabs you share.

Use **New sector** on the galaxy's picture and tap where it lies to make a **Sector**: a hex map of that part of the galaxy, one hex to 5 light years. The sector generator picks its size, how many systems and how many of them are only rumours, lanes, backdrop, colour and seed. On a Milky Way page you can start from the **Local Bubble**, the Sun and real stars within about 25 light years. On the sector's **Hex map**, tap a hex to name its system, set its star, mark it charted or a rumour, write a note, join it to others by lanes, and see how far it is from another system and how long light takes to cross. **Sector settings** generates it again, keeping the systems you changed.

On a sector's hex, **Survey this system** makes a **Star system** page for it, inside the sector. Its **Survey chart** shows the system moving around its star, with the green zone (where water can stay liquid) and the frost line, then lists its worlds out from the star, zone by zone, with the time to travel between neighbours. Tap a world to see the sky from its surface and change anything about it: kind, size, gravity, temperature, air, water, resources, hazard, life, who settled it and which organization holds it. Fields you change are marked as edited. Lock a world to keep it when you run the survey again, roll just that world again, or remove it. The side shows the system's hooks (a lure, a danger and a GM-only secret) and a travel calculator. **Survey settings** picks the star and companions, a premise, how many worlds and of what kinds, the era, Realistic or Pulp science and which organizations have a foothold, then runs the survey again. Sol can use real data. **FTL drives**, set once per galaxy, add faster-than-light travel times to hex maps and survey charts: a multiple of light speed, jumps with a range and a recharge, or lanes only. The Survey chart tab is for the GM.

When a world matters to your story, open it on the chart and press **Chart this world**. It becomes a place page inside the system, starting from its notes. Its **World** tab shows the sky from its surface and all its survey fields, which you can change there or on the chart: both stay the same. It lists its moons (or the planet it orbits), each of which you can chart too. If you remove a charted world from the chart, its page stays with its last survey.

**Check with your AI**, beside the Survey chart, sends the survey in words (the star, its zones, every world and moon, the belts, the lure and the danger, never the secret) with pages you pick, such as the galaxy, the sector or your lore, to one of your own AI connections. It says what fits, what is a stretch and what doesn't fit, quoting your pages, and can offer a fix to one world's temperature, gravity, size, air, water, life, resources or settlement, which you apply with a button. Nothing changes until you do. Without an API key, copy the prompt into your AI app.

In **Survey settings**, **Start from: A setting (AI)** asks your own AI to build the system from a setting you name (a book, game, film or your own) and, if you like, a system in it: its star, worlds and moons in order, what they are like, and a lure, a danger and a secret. Where the answer leaves something out, RPG Tools fills it in to fit the world's kind and orbit. You see it in the preview before you use it, and worlds you locked or charted stay. It is built when you ask, for your campaign only: RPG Tools ships no setting's content. Without an API key, copy the prompt into your AI app and paste its answer back.

The Map Creator's stamp library has four space groups for drawing star maps, system maps and stations: **Stars** (each star class, white dwarf, neutron star, pulsar, black hole, brown dwarf, red giant, protostar), **Worlds** (rocky, desert, magma, ice, ocean, jungle, toxic, gas and ice giants, ringed giant, rogue planet, shattered world, tidally locked world, city world, moon), **Space** (asteroids, comet, debris disc, nebula, dust cloud, ion storm, wormhole, solar flare, anomaly, supernova remnant, orbit ring, green zone band, hazard, waypoint) and **Stations and ships** (stations, shipyard, jump gate, beacon, satellite, mining rig, defense platform, derelict, wreck field, space elevator, habitat cylinder, Dyson swarm, relay buoy, starship, shuttle, fighter, fleet). Their tiles in the library sit on a dark sky so the light shapes show.

## Ships and vehicles

Choose **Vehicle** as the entry type to make a ship, airship, carriage, car or anything else the party rides in. A vehicle page opens on its **Overview**: pick its type (Starship, Sailing ship, Airship, Carriage or Car), write its model line, choose an owner (a character or organization) and its captain, coachman or driver (a character), add a picture or deck plan (otherwise the type's outline shows), set where it is (a place page or a few words), and keep its gauges (such as Hull, Shields and Fuel) up to date with − and +. Each type has its own stats and Right now fields. Every value has an eye: a hidden value never reaches the player site. Players see the Overview tab only when its tab visibility is Player visible. The page's text is the **Description** tab. Changing a vehicle's type keeps the values whose names match. The gear beside the type opens **Vehicle types**, where you make your own kinds of vehicle for the world (a walker, a dragon-drawn barge, a submarine) or change the ready-made ones: the outline, what the commander and Crew tab are called, and the gauges, stats, Right now fields, stations and unnamed counts each type has. Saving tidies the world's vehicles: values for fields a type no longer has are dropped, and vehicles of a deleted type become the first type. The **Crew** tab (Retinue on a carriage, Passengers in a car) lists the vehicle's stations: rename them, add or remove them, seat a character page or a typed name, and pin a station to show it on the Overview's picture. Below the stations are the manifest of everyone else aboard, with their roles, and unnamed counts such as Marines or Outriders. The Crew tab has its own tab visibility, and every station, person and count has an eye. A character or organization page lists the vehicles it owns, commands or crews in its side panel. An AI connection can create vehicle pages (empty, or rolled up from a template) and read a vehicle's sheet; one that may only see what players see reads only the shared parts. An organization's Holdings also show the vehicles it owns, and on the player pages a character lists the shared vehicles it owns, commands or crews (only the roles players can see). The **Hold** tab (Cargo hold on a starship, Luggage on a carriage) lists what the vehicle carries, with amounts in the type's unit, against a capacity if you set one. The **Systems** tab (Guns and rigging on a sailing ship, Mods on a car) lists weapons, engines, sails or anything else, each Working, Damaged or Offline, with a note and a roll such as 2d6+1: click the roll to roll it, players too when the tab is shared. Both tabs have their own tab visibility and every line has an eye; you can rename them and the cargo unit in Vehicle types. The dice beside the type opens **Roll up a vehicle**: choose a type and a template (a freighter, a galleon, a mail coach, a wasteland rig…) and reroll until you like it, then fill this page with it (crew, owner, location and what players can see stay as they are) or add it as a new vehicle page. The **Log** tab keeps what happened to the vehicle, newest first: pick Voyage, Battle, Repairs, Trade or Note, add an in-game date if you like, and write it down. The tab has its own visibility, and each entry has an eye. When the campaign is paired with a Maptable campaign, **Add to Maptable** beside the type opens Maptable and puts the vehicle on the open scene as a large token (3×3 for ships and airships, 2×2 for the rest, or the size its picture is framed at).

## Relationships

Every page except folders and task lists has a **Connections** tab (a quest shows its ties in its own Connections tab). **Add a tie**, or drag a page onto the tab from the sidebar, then pick the kind of tie: each reads from both ends, such as Parent of and Child of, or Owes a debt to and Is owed by. A tie can carry a note, when it began and ended, how each side feels, and whether players see it. A GM-only tie can have a cover story: another kind of tie that players see instead. **Kinds of tie** renames the built-in kinds and makes your own for anything that joins two pages. Organization members, vehicle crew, quests and siblings found through shared parents are listed too, without being added.

**Relationships**, beside the Codex in the sidebar, draws every tie in the campaign as one web. Filter it by group of tie and kind of page, draw organization members and vehicle crew, and click a page to focus on it and the pages around it (one or two steps out), or a line to see and change its ties. **What players see** shows the web as players would: shared ties, and cover stories in place of GM-only ties, between pages they can read. Players get each page's shared ties on its Connections tab.

**Family trees**, the other half of Relationships, draws a family from its family ties (Parent of, Married to, Sibling of, Guardian of, and any kind of tie set to draw on a family tree): eldest at the top, couples side by side with a double line, children under them, wards on a dashed line and GM-only ties dashed in amber. Pick a family (each organization of type Noble house, House, Family, Clan or Dynasty, then any group of relatives no such organization covers) or **Start from a person**. A house's tree follows its own line: someone who married in is drawn without their own parents, and their box says which other house they come from. Click someone to see their family on the side and add a parent, partner, child or sibling, either a page that exists or a new character by name. Their role on the organization's Profile (Heir, Abbess) shows on their box. On a phone the tree is an outline, eldest first. Family organizations also get a **Family tree** tab.

Two generators fill this in from built-in name and trait lists. Nothing is saved until you add the result.

- **Generate a family**, on Family trees, builds a family around a character or starts a new one. You choose:
  - how many generations go above (none, parents, or grandparents too);
  - whether to add a partner and children;
  - how many children each couple has;
  - how many twists (quiet, some or scandalous). Twists include a secret child shown to players as a ward, rival or estranged siblings, an old flame and a betrayal, and most are GM only.
  - a name style, and whether people who marry in take the family name. It can also make a Family organization page for them.

  Reroll until you like it, then add every character and tie at once. New characters start GM only.
- **Generate ties**, on the Web, takes the pages you pick (or a few at random, or an organization's members) and an amount of each group of tie, from Off to Lots. It then suggests ties that fit those pages, each with a note, skipping pairs that are already tied. You can change each suggestion's kind, note and GM-only setting, keep it through rerolls, or leave it out.

In a campaign with an AI connection made with your own API key, both generators also have **Write with AI**. Add an optional steer (a tone, a theme, a hook) and it rewrites the notes from what the pages say. For a generated family it also writes a line about each new person, which becomes their page. It reads only what that connection may see: a connection kept to what players see leaves GM-only pages and ties out, and those keep their built-in notes. Ticked suggestions keep their notes unless every one is ticked, and a reroll goes back to the built-in notes. Nothing is saved until you add the result, and the tokens count against the connection's monthly limit.

## Players and AI access

Player links show only material explicitly shared with players, with private notes and unrevealed map areas filtered. Anyone holding a player link can read its shared content. Replace or revoke the link to stop subsequent access. Already issued signed image URLs can remain valid for up to five minutes; downloaded copies cannot be recalled.

In encyclopedia Connections, select a campaign and create a read-only agent key. It includes private GM material for that campaign and shared world lore, so do not give it to players. It cannot read other campaigns or edit the workspace. Keys are independent of Maptable keys and can be replaced/revoked.

For an MCP-capable coding assistant, run Node 22 with `scripts/encyclopedia-mcp.mjs` and supply these environment variables privately through the client's configuration:

```text
RPG_TOOLS_URL=https://YOUR-DEPLOYMENT.vercel.app
ENCYCLOPEDIA_AGENT_KEY=enc_YOUR_GENERATED_CAMPAIGN_KEY
```

Available tools: `list_worlds`, `read_campaign`, `search_campaign`, `read_article`. Client support varies; a model name alone does not provide MCP or repository access. Codex, Claude, T3Code, DeepSeek and Grok can work on the source using AGENTS.md and the prompt in GITHUB_SETUP.md.

The optional `scripts/campaign-sync.mjs` exports campaign JSON and Markdown to a local Git checkout. Run with `node --experimental-strip-types`; consult its `--help` and the encyclopedia Connections panel. Saving in the browser does not push to GitHub. Campaign exports may contain private GM notes: keep them separate from this application's source repository.

## Character sheets (Google Sheets)

A character page can link one Google Sheet. Its Profile tab then shows a Character sheet section with chosen cells copied from it: hit points (with a maximum and your own label, such as Stress), AC, Initiative, other stats, and rolls listed with their formulas. The copy is stored on the character (`character.sheet`); rolling, Maptable, Discord and writing back to the sheet are not part of this yet.

- **Published link (no setup).** In Google Sheets choose File, Share, Publish to the web, pick the tab and Comma-separated values (.csv), and paste the link under Link a character sheet. Publishing makes the sheet readable by anyone with the link. The server reads only `docs.google.com`, up to 2 MB.
- **Sign in with Google (needs one-time setup below).** The browser signs in with Google Identity Services, Google's own file picker lets the GM choose one sheet, and the browser reads it with the Sheets API. The scope is `drive.file`, which can open only files picked in the app. No token or sheet is stored on our server.
- **Which cells.** A tab named `RPG Tools` whose first row is Name, Value, Roll is read row by row (a Roll makes a roll; HP, Max HP, AC and Initiative fill their slots). Otherwise the GM clicks label and value cells in a grid. The dialog's Download template link gives an example CSV to import as that tab.
- **Rolling (GM).** The sheet section's Rolls area lists the sheet's roll items by group (Skills, Saves, Attacks, Other); "Longbow attack" and "Longbow damage" become one row with an Attack and a Damage button, and a roll item with only a bonus such as +5 rolls 1d20 plus it. Pick Advantage, Normal or Disadvantage before a roll (it resets to Normal): a single d20 becomes 2d20kh1 or 2d20kl1, and other rolls are rolled twice keeping the higher or lower total. Notation: `1d20+5`, `4d6kh3` / `2d20kl1`, `2d6!` exploding, `5d10>=8` count successes (dice at or over 8), `2d20<=14` count dice at or under 14, `4dF` plus/minus dice. Rolls show in the roll card (Send to Discord, or Always) titled Character · Roll, and the latest are kept in a per-browser roll log. In Maptable, a token linked to a character with a sheet has Roll from <name>'s sheet in its menu. Players roll as described under Players.
- **Players.** When the character's Stats tab is player visible, players see the copied title, values and formulas, read only. They never receive the spreadsheet id, the published link, who linked it or the cell references, and a players-only AI connection follows the same rule.
- **Players linking and rolling.** A signed-in member who may edit a character page (Who can edit) sees Link my sheet, Refresh, Open and Unlink there. They link a published link (read by the server with the same limits) or a Google file they pick (read in their own browser). They can change a sheet only when the page has none or they linked it; a sheet the GM linked stays the GM's. Their sheet is visible to them even while the Stats tab is GM only, and the GM page says Linked by <their name>. For a published link the server reads the sheet again when it is linked, so the stored values come from the sheet; a Google file read in the player's own browser is accepted as read, because it is their own sheet. Their rolls are made on the server from the stored formula, posted to the campaign's Discord channel as the character (with that page's own picture, if it has one) when one is set, and shown in the roll card. Anyone else (share-link viewers, other characters) sees the stats and can roll locally, which stays on that device. Only the member who linked a sheet is given its open link.
- **Write HP back (opt in, Google sign-in links only).** On a sheet linked with Google sign-in that has an HP cell, the sheet section shows a **Write HP back to the sheet** switch (off by default; "When HP changes here, update the cell in the sheet"). Published links can't be written to and say so. With it on, the section gets HP controls (lose 5 or 1, gain 1 or 5, or set an exact number). A change lands on the page at once; after 1.5 seconds without another change the browser writes the latest number to the HP cell, and only that cell (never Max HP or anything else), using `spreadsheets.values.update` with `valueInputOption=RAW` so the number is stored exactly as a number and is never parsed as a date or formula. Whole numbers from -9999 to 99999 only. It writes with the signed-in person's own in-memory Google token (nothing is stored on the server, no refresh token, no new scope: `drive.file` already covers sheets they picked). It never opens a Google pop-up by itself: with no live sign-in the page says "Sign in with Google to write HP back" and a button. Before writing it reads the cell; if the sheet's HP changed since it was read it shows "The sheet's HP changed to X since it was read" with **Use the sheet's value** or **Write ours**, and a cell holding a formula is never overwritten. After a write the stored copy's HP and read time are updated. Only the person who linked the sheet can turn it on: a sheet a player linked from their own Google account can't be switched on by the GM, and the player pages don't offer it yet. Players and the AI read-only views never receive the setting (`playerSheet()` is an allowlist). **In Maptable** (GM only; not for a co-GM or the player view): a token placed from an Encyclopedia character whose sheet has write-back on writes its HP too. The change is noticed wherever the scene changes (the HP card, the zero-HP rules, undo and redo) in this tab; changes that arrive from another tab or device or from an AI over MCP are not written (only the tab that made a change writes it), and if you leave Maptable with a change still waiting it is sent only when a Google sign-in is live, otherwise it is dropped. Several tokens linked to the same character share that character's sheet HP (the last change wins), waits 1.5 seconds per character, then goes through the same check and write. The token's menu item Roll from <name>'s sheet opens a panel with the same Write HP back switch and the status line (\"HP written to the sheet just now\", \"Couldn't write HP: ...\" or \"Sign in with Google to write HP back\" with a button). If the sheet's HP changed, **Use the sheet's value** also sets the token's HP. The stored copy is updated by a small route (`POST /api/encyclopedia/sheet-hp`) that changes only that one character's sheet HP and read time on the newest saved Encyclopedia, so other edits are kept. Maptable checks a copy of the Encyclopedia it already loaded to decide whether a character writes at all, so a switch turned on in another tab is picked up once the panel is opened.

### One-time Google setup (site owner)

1. In the Google Cloud console create a project. Note its **project number** (Project settings).
2. Enable the **Google Sheets API**, **Google Picker API** and **Google Drive API** in this same project. The Sheets API must be on for reading and for writing HP back; no new scope or OAuth setting is needed for write-back.
3. OAuth consent screen: user type **External**, add only the scope `.../auth/drive.file`. While in Testing, add each GM as a test user; publish the app when ready for others.
4. Credentials, Create OAuth client ID, type **Web application**. Add the site's origins as Authorized JavaScript origins (for example `https://dreams-tools-sable.vercel.app` and `http://localhost:5173`). No redirect URI is needed.
5. Credentials, Create API key. Restrict it to the **Google Picker API** and **Google Sheets API**, and to the site's HTTP referrers.
6. Set these in the deployment's environment (they are `NEXT_PUBLIC_`, so they are visible in the browser by design) and redeploy:

```text
NEXT_PUBLIC_GOOGLE_CLIENT_ID=<the OAuth client ID>
NEXT_PUBLIC_GOOGLE_API_KEY=<the restricted API key>
NEXT_PUBLIC_GOOGLE_APP_ID=<the project number>
```

Until all three are set, the dialog shows Sign in with Google disabled with "The site owner hasn't set up Google sign-in yet. Use a published link for now." The app sends no Content-Security-Policy header today, so nothing needs allowing. If one is added later, the Google option loads scripts from `accounts.google.com` and `apis.google.com`, frames the picker from `docs.google.com`, opens a sign-in pop-up on `accounts.google.com`, and calls `sheets.googleapis.com` and `www.googleapis.com`. Check the browser console for refusals after adding a policy, because the picker may also load assets from other Google hosts.
